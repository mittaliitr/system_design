Chapter 2 – Thread Creation & Management

Four Methods Rule Thread Behavior

These four methods are the foundation of thread coordination:

  • start() → Begin execution
  • join() → Wait for completion
  • sleep() → Pause without releasing locks
  • interrupt() → Gracefully stop or wake up
Golden Rule: Never call run() directly. Always use start().

Method Deep Dive

start()
public void start()
Schedules the thread for execution. Creates a new OS thread and calls run().
Pitfall: Calling start() twice → IllegalThreadStateException 
Thread t = new Thread(() -> work());
t.start(); // Correct
t.run();   // Wrong! Runs in current thread
join()
public final void join() throws InterruptedException
Current thread waits until this thread terminates. Useful for sequencing tasks.
Pitfall: Can cause deadlock if not used carefully. 
Thread worker = new Thread(task);
worker.start();
worker.join(); // Main waits for worker
sleep()
public static void sleep(long millis) throws InterruptedException
Pauses current thread for specified time. Does NOT release locks.
Pitfall: sleep() in synchronized block holds the lock. 
synchronized(lock) {
    Thread.sleep(1000); // Lock still held!
}
interrupt()
public void interrupt()
Sets interrupt flag. Cooperating threads check isInterrupted() or catch InterruptedException.
Pitfall: Does not force stop. Thread must cooperate. 
while (!Thread.currentThread().isInterrupted()) {
    // do work
}

Real-World Scenario: Graceful Shutdown

Background Worker with Clean Exit
public class Worker implements Runnable {
    private volatile boolean running = true;

    @Override
    public void run() {
        while (running) {
            try {
                System.out.println("Working...");
                Thread.sleep(1000); // Responds to interrupt
            } catch (InterruptedException e) {
                System.out.println("Interrupted!");
                Thread.currentThread().interrupt(); // Restore flag
                break;
            }
        }
        System.out.println("Clean shutdown.");
    }

    public void shutdown() {
        running = false;
    }
}

// Usage
Worker task = new Worker();
Thread thread = new Thread(task);
thread.start();

// Later...
thread.interrupt(); // Graceful stop
thread.join(2000);  // Wait up to 2s
Best Practice: Check isInterrupted() + catch InterruptedException + restore flag

Top 5 Mistakes (and Fixes)

Calling run() directly
Fix: Always call start()
Swallowing InterruptedException
Fix: Re-interrupt: Thread.currentThread().interrupt()
Using sleep() for synchronization
Fix: Use wait()/notify() or CountDownLatch
Infinite loops without interrupt check
Fix: Check isInterrupted()
join() without timeout
Fix: Use join(5000) to avoid hangs

Key Takeaways

1. start() → creates OS thread; run() → same thread

2. join() → wait for finish; use with timeout

3. sleep() → pause, keeps locks

4. interrupt() → cooperative cancellation

5. Always restore interrupt flag in catch block

6. These 4 methods = 90% of thread coordination
