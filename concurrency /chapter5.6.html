5.6 SynchronousQueue

Zero-Capacity Direct Handoff

The weirdest — and often fastest — BlockingQueue

Chapter 5 – Blocking Queues & Producer-Consumer

SynchronousQueue — No Storage, Pure Handoff

SynchronousQueue has capacity = 0.
Every put() must wait for a matching take() and vice versa.

It’s not a queue — it’s a rendezvous point.

Direct Producer ↔ Consumer Handoff

Hand
Capacity = 0
Hand
Behavior:
• put(item) blocks until another thread calls take()
• take() blocks until another thread calls put()
• Direct handoff — no buffering

Simple Producer-Consumer with SynchronousQueue

BlockingQueue handoff = new SynchronousQueue<>();

// Producer thread
new Thread(() -> {
    String item = produce();
    try {
        handoff.put(item);  // Waits for consumer
        System.out.println("Item handed off");
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}).start();

// Consumer thread
new Thread(() -> {
    try {
        String item = handoff.take();  // Waits for producer
        consume(item);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}).start();

Fair vs Non-Fair Mode

// Non-fair (default) — higher throughput
SynchronousQueue queue = new SynchronousQueue<>();

// Fair — FIFO ordering (slightly slower)
SynchronousQueue fairQueue = new SynchronousQueue<>(true);
Fair = true: Waiting threads served in arrival order
Fair = false: Faster, but possible starvation

The Most Important Use Case

Executors.newCachedThreadPool() uses SynchronousQueue internally! 
// Under the hood of newCachedThreadPool()
ExecutorService pool = new ThreadPoolExecutor(
    0, Integer.MAX_VALUE,
    60L, TimeUnit.SECONDS,
    new SynchronousQueue()  // Direct handoff!
);
Why?
• No idle threads → zero overhead when idle
• New task → either reuse idle thread or create new
• Direct handoff → maximum responsiveness

When to Use SynchronousQueue

Perfect for:
• Executors.newCachedThreadPool()
• Actor systems (direct message passing)
• Request-response patterns
• When you want no buffering
Never for:
• Bounded work queues
• Backpressure
• When you need ordering

Key Takeaways

1. SynchronousQueue = capacity 0 → direct handoff

2. put() waits for take() and vice versa

3. Powers newCachedThreadPool()

4. Zero memory overhead, maximum speed

5. Optional fairness (true constructor)

6. Use when you want unbounded threads with no idle cost
