0.3 Memory Hierarchy: Registers to Disk

Why Your CPU Waits 99% of the Time

Chapter 0 – Computer Architecture & Concurrency Foundations

The Speed vs. Capacity Trade-Off

The CPU is blazing fast — but memory isn't. To solve this, computers use a memory hierarchy: small, fast, expensive at the top; large, slow, cheap at the bottom.

Analogy: It's like a student's desk:
  • Hand: Holding pen (registers)
  • Desk: Open notebook (L1 cache)
  • Backpack: All books (RAM)
  • Library: Archives (SSD)

Latency in Human Terms

Memory Level Latency (ns) Human Analogy (if 1 CPU cycle = 1 second)
Register 0.5 ns 1 second
L1 Cache 1–3 ns 2–6 seconds
L2 Cache 4–10 ns 8–20 seconds
L3 Cache 10–20 ns 20–40 seconds
RAM 100 ns 3.3 minutes
SSD 100,000 ns 1.2 days

Cache Miss = CPU Stall!
When data isn't in cache, the CPU waits — like waiting for a package from another country.

Virtual Memory: The Illusion of Infinite RAM

The OS creates a virtual address space for each process. It maps virtual pages to:

  • Physical RAM
  • Or disk (swap file)
// Java sees 8 GB of "RAM"
int[] array = new int[2_000_000_000];  // 8 GB

// OS may swap inactive pages to SSD
// → Page fault = 10,000× slower!
Pro Tip: Avoid OutOfMemoryError by understanding -Xmx and swap.

Why This Matters in Java Multithreading

In Java: 

volatile int counter = 0;

void increment() {
    counter++;  // 1. Load from RAM/cache
                // 2. Increment in register
                // 3. Store back to RAM
}

Without volatile: Thread might keep value in register → stale data!

Key Insight: volatile = "Flush register → RAM after write, reload before read"

Key Takeaways

1. Memory is a pyramid: fast/small → slow/large.

2. CPU spends 99% of time waiting for memory.

3. Cache misses = performance killer.

4. volatile forces register ↔ RAM sync.

5. Virtual memory uses SSD as backup RAM.
