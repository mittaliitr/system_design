Key:
• Tomcat uses virtual threads (default in Spring Boot 3.2+)
• Each request → one virtual thread
• Blocking calls (JDBC, RestTemplate) → just pause virtual thread
• No wasted carrier threads

Spring Boot Configuration (Just 2 Lines!)

# application.yml
spring:
  threads:
    virtual:
      enabled: true   # That's it!

server:
  tomcat:
    threads:
      max: 200      # Carrier threads (platform threads)
      min-spare: 10
Result:
• 200 carrier (platform) threads
• Unlimited virtual threads
• All existing blocking code just works

Plain Old Controller — Now Scales to Millions

@RestController
@RequestMapping("/api")
public class GatewayController {

    private final WebClient webClient;  // Blocking or reactive

    @GetMapping("/users/{id}/dashboard")
    public Dashboard getDashboard(@PathVariable Long id) {
        // All blocking calls — on virtual thread!
        User user = userService.getUser(id);                    // JDBC
        List orders = orderService.getRecent(id);        // RestTemplate
        List payments = paymentService.getRecent(id);  // HTTP

        return new Dashboard(user, orders, payments);
    }
}

Bonus: StructuredTaskScope for Parallel Calls

@GetMapping("/users/{id}/dashboard")
public Dashboard getDashboard(@PathVariable Long id) {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        var user = scope.fork(() -> userService.getUser(id));
        var orders = scope.fork(() -> orderService.getRecent(id));
        var payments = scope.fork(() -> paymentService.getRecent(id));

        scope.join();           // Wait for all
        scope.throwIfFailed();  // Propagate error

        return new Dashboard(
            user.resultNow(),
            orders.resultNow(),
            payments.resultNow()
        );
    }
}
