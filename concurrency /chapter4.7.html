Chapter 4 – Executors & Thread Pools

Spring Boot Runs on Thread Pools

Every Spring Boot web app is a highly concurrent server.
One JVM process → one or more thread pools → thousands of requests.

Default: Tomcat + max-threads=200 → handles 200 concurrent requests out of the box.

Embedded Web Servers & Their Pools

Tomcat (Default)
server.tomcat.max-threads=200
server.tomcat.min-spare-threads=10
Traditional servlet → blocking → one thread per request
Undertow
server.undertow.worker-threads=64
server.undertow.io-threads=8
Non-blocking I/O → fewer threads, higher throughput
Netty (WebFlux)
spring.webflux.reactor.event-loop-threads=8
Reactive → event loop (not thread-per-request)

@Async — Fire-and-Forget Background Tasks

@EnableAsync
@Configuration
class AsyncConfig implements AsyncConfigurer {
    @Override
    public Executor getAsyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.setMaxPoolSize(50);
        executor.setQueueCapacity(1000);
        executor.setThreadNamePrefix("Async-");
        executor.initialize();
        return executor;
    }
}

@Service
class EmailService {
    @Async
    public CompletableFuture sendEmail(User user) {
        // Runs on Async- thread pool
        emailSender.send(user);
        return CompletableFuture.completedFuture(null);
    }
}
Default: SimpleAsyncTaskExecutor → new thread per task!
Always configure your own ThreadPoolTaskExecutor

Web MVC (Blocking) vs WebFlux (Reactive)

Spring Web MVC
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {
    return userRepo.findById(id).block(); // Blocks thread!
}
Thread-per-request → 200 threads max
Spring WebFlux
@GetMapping("/users/{id}")
public Mono getUser(@PathVariable Long id) {
    return userRepo.findById(id); // Non-blocking
}
Event loop → 10000+ requests with few threads

Production-Grade Thread Pool Config

@Configuration
public class ThreadPoolConfig {
    @Bean("taskExecutor")
    public TaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(16);
        executor.setMaxPoolSize(64);
        executor.setQueueCapacity(1000);
        executor.setThreadNamePrefix("app-");
        executor.setRejectedExecutionHandler(new CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(60);
        return executor;
    }
}
Rejection Policy: CallerRunsPolicy → backpressure
Graceful shutdown: Wait for tasks to complete

Key Takeaways

1. Spring Boot web apps = thread-per-request by default

2. Tomcat default: max-threads=200

3. @Async without config = new thread per task!

4. Always configure ThreadPoolTaskExecutor

5. WebFlux = reactive → few threads, high throughput

6. Use CallerRunsPolicy + graceful shutdown

7. Monitor with Micrometer
