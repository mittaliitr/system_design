4.5 Fork/Join Framework

Divide-and-Conquer Parallelism

The engine behind parallel() streams and massive speedup

Chapter 4 – Executors & Thread Pools

Divide et Impera — Divide and Conquer

The Fork/Join framework (Java 7+) is designed for recursive, divide-and-conquer algorithms.

Core Idea:
Split task → solve sub-tasks in parallel → merge results
Work-stealing keeps all cores busy

ForkJoinPool + RecursiveTask/RecursiveAction

// Extend RecursiveTask for result
class SumTask extends RecursiveTask {
    private final long[] array;
    private final int start, end;
    private static final int THRESHOLD = 1000;

    SumTask(long[] array, int start, int end) {
        this.array = array; this.start = start; this.end = end;
    }

    @Override
    protected Long compute() {
        if (end - start <= THRESHOLD) {
            // Base case — compute directly
            long sum = 0;
            for (int i = start; i < end; i++) sum += array[i];
            return sum;
        }

        int mid = (start + end) / 2;
        SumTask left = new SumTask(array, start, mid);
        SumTask right = new SumTask(array, mid, end);

        left.fork();                  // Async execute
        long rightResult = right.compute();
        long leftResult = left.join(); // Wait for result

        return leftResult + rightResult;
    }
}
Key Methods:
• fork() → submit to pool (async)
• join() → wait for result
• compute() → called directly or via fork

When to Use Fork/Join

Perfect for:
• Merge sort, quicksort
• Matrix multiplication
• Image processing (blur, filters)
• Large tree traversals
• Any recursive divide-and-conquer
Not for:
• I/O-bound tasks
• Very small tasks (overhead)
• Irregular workloads

The Hidden Hero: commonPool()

// Used by:
stream.parallel()
CompletableFuture.supplyAsync()
Arrays.parallelSort()
Parallel GC (G1, ZGC)

// Size: Runtime.getRuntime().availableProcessors() - 1
ForkJoinPool.commonPool().getParallelism(); // e.g., 7 on 8-core
Never block inside commonPool!
No Thread.sleep(), no blocking I/O → starves parallel streams

Key Takeaways

1. Fork/Join = divide-and-conquer + work-stealing

2. Extend RecursiveTask or RecursiveAction

3. fork() → async, join() → wait

4. Work-stealing keeps all cores busy

5. Powers parallel() streams and CompletableFuture

6. Never block in commonPool()
