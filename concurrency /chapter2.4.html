2.4 Daemon Threads

Background Workers That Die When the JVM Exits

The silent helpers — GC, logging, timers

Chapter 2 – Thread Creation & Management

User Threads vs. Daemon Threads

Every thread is either User or Daemon. The JVM only exits when all user threads finish.

Rule of JVM Shutdown:
JVM exits to only if no user threads are alive.
Daemon threads are killed abruptly on exit.

Head-to-Head: User vs Daemon

User Thread Default
Keeps JVM alive. Must finish or be interrupted for clean shutdown.
main thread
worker threads
Spring @Async tasks
your business logic
Daemon Thread Background
Killed automatically when JVM exits. Ideal for non-critical background tasks.
Garbage Collector
Finalizer thread
Timer/Scheduled tasks
Logging appenders

How to Create a Daemon Thread

// Must set BEFORE start()
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("Background task...");
        try { Thread.sleep(1000); }
        catch (InterruptedException e) { break; }
    }
});

daemon.setDaemon(true);  // Critical: before start()
daemon.start();
Golden Rule: setDaemon(true) MUST be called before start().
After start() to IllegalThreadStateException

Demo: Daemon vs User — JVM Exit Behavior

What Happens on main() Exit?
public class DaemonDemo {
    public static void main(String[] args) throws Exception {
        Thread user = new Thread(() -> loopForever("User"));
        Thread daemon = new Thread(() -> loopForever("Daemon"));

        daemon.setDaemon(true);  // Only this one dies

        user.start();
        daemon.start();

        Thread.sleep(3000);
        System.out.println("main() exiting...");
        // JVM waits for user, kills daemon
    }

    static void loopForever(String name) {
        while (true) {
            System.out.println(name + " running...");
            try { Thread.sleep(500); }
            catch (InterruptedException e) { break; }
        }
    }
}
Output:
User running...
Daemon running...
... (3 seconds)
main() exiting...
to User keeps JVM alive
to Daemon killed abruptly

Best Practices & Pitfalls

Do Use Daemon For
to Background logging
to Metrics collection
to Cache refresh
to Heartbeat monitors
Never Use Daemon For
to Database transactions
to File writes
to Message processing
to Any state that must persist
Critical: Daemon threads do not run finally blocks on abrupt JVM exit.
Never put cleanup (close DB, flush logs) in daemon finally.

Key Takeaways

1. User threads keep JVM alive

2. Daemon threads are killed on JVM exit

3. Set setDaemon(true) before start()

4. finally blocks may not run in daemons

5. Use for non-critical background tasks only

6. GC, Timer, Logging = daemons by default
