6.4 Scoped Values

The Modern, Immutable Replacement for ThreadLocal

Inheritable, immutable context — perfect for virtual threads

Chapter 6 – Project Loom

ThreadLocal = Leaky, Mutable, Dangerous

ThreadLocal has been the standard way to pass context (user ID, request ID, etc.) for 25 years.

Problems:
• Mutable → race conditions
• Not inherited by child threads
• Memory leaks in thread pools
• Manual cleanup required 
// Classic ThreadLocal problems
private static final ThreadLocal userHolder = new ThreadLocal<>();

public void processRequest() {
    userHolder.set(currentUser);
    try {
        doWork();  // Must remember to remove!
    } finally {
        userHolder.remove();  // Easy to forget!
    }
}

ScopedValue — Immutable & Inherited

// Java 21+ — immutable, inherited, no leaks!
private static final ScopedValue USER = ScopedValue.newInstance();

ScopedValue.where(USER, currentUser)
    .run(() -> {
        doWork();               // USER.get() works
        executor.submit(() -> {
            // Inherited automatically!
            log("User: " + USER.get().id());
        });
    });
Magic:
• Immutable binding
• Inherited by all child virtual threads
• Automatic cleanup — no leaks
• Perfect for request context, transaction ID, logging MDC

Real-World: Web Request Context

Spring Boot + Virtual Threads + Scoped Values
private static final ScopedValue REQUEST_ID = ScopedValue.newInstance();
private static final ScopedValue CURRENT_USER = ScopedValue.newInstance();

@GetMapping("/orders")
public String getOrders() {
    return ScopedValue.where(REQUEST_ID, generateId())
        .where(CURRENT_USER, authService.getCurrentUser())
        .call(() -> orderService.getOrders());  // All children inherit!
}

@Service
class OrderService {
    public String getOrders() {
        log("Processing for user: " + CURRENT_USER.get().id()
            + " req: " + REQUEST_ID.get());
        // Works even in @Async or virtual threads!
    }
}

Key Takeaways

1. ScopedValue = immutable, inheritable ThreadLocal replacement

2. Use ScopedValue.where(key, value).run/call()

3. Automatically inherited by all child virtual threads

4. No memory leaks — scope ends, value gone

5. Perfect for request IDs, user context, MDC logging
