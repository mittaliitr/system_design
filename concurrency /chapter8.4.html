Evolution of DoorDash’s Java Stack

2013–2018: Classic Java
  • Spring Boot + Tomcat
  • Thread-per-request model
  • Thread pools everywhere
  • Blocking JDBC, RestTemplate
2019–2023: Reactive Revolution
  • WebFlux + Netty
  • Non-blocking drivers (R2DBC, WebClient)
  • Reduced thread count dramatically
  • Complex code, steep learning curve
2024+: Project Loom Era
  • Virtual threads enabled in production
  • Back to simple blocking code
  • 10–100× reduction in thread count
  • Massive simplification of codebase
Quote from DoorDash Engineering (2023):
“Virtual threads allow us to write simple, readable code while achieving the scalability we previously needed reactive programming for.”
