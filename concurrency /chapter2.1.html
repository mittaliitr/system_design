2.1 extends Thread vs. implements Runnable

The Right Way to Create Tasks in Java

Why 99% of production code uses Runnable

Chapter 2 – Thread Creation & Management

Two Ways, One Goal

Java gives you two ways to define what a thread does:

  • extends Thread → IS-A thread
  • implements Runnable → HAS-A task
Rule #1: Use Runnable unless you have a very good reason not to.

Head-to-Head: Code & Design

extends Thread Legacy 
class Worker extends Thread {
    private final String name;

    public Worker(String name) {
        this.name = name;
    }

    @Override
    public void run() {
        System.out.println(name + " working...");
        // task logic
    }
}

// Usage
new Worker("Alice").start();

Pros

  • Direct access to Thread methods
  • Simple for beginners

Cons

  • No inheritance flexibility
  • Cannot return values
  • Cannot throw checked exceptions
  • Tightly coupled to Thread
implements Runnable Recommended 
class Worker implements Runnable {
    private final String name;

    public Worker(String name) {
        this.name = name;
    }

    @Override
    public void run() {
        System.out.println(name + " working...");
        // task logic
    }
}

// Usage
new Thread(new Worker("Alice")).start();

Pros

  • Supports composition
  • Works with ExecutorService
  • Can implement multiple interfaces
  • Decoupled from Thread

Cons

  • Slightly more verbose

When Each Approach Fails

Scenario 1: You Need Inheritance
// Problem with extends Thread
class SpecialWorker extends Worker {  // Compile error!
    // Cannot extend both Thread and Worker
}
Scenario 2: Return a Result
// Need Callable instead
Callable task = () -> {
    return computeResult();
};

Future future =
    executor.submit(task);
Solution: Use Runnable to task, Callable to result, ExecutorService to execution.

Modern Best Practices

// 1. Use lambda (Java 8+)
Runnable task = () -> System.out.println("Hello");

// 2. Use ExecutorService
ExecutorService executor = Executors.newFixedThreadPool(4);
executor.submit(task);

// 3. For results: Callable + Future
Callable callable = () -> "Result";
Future future = executor.submit(callable);

// 4. Never extend Thread in production
Framework Support:
to Spring @Async to Runnable or Callable
to JavaFX to Task extends Runnable
to Android to AsyncTask to Runnable

Key Takeaways

1. extends Thread to Legacy, inflexible

2. implements Runnable to Flexible, composable, future-proof

3. Use Callable when you need return values

4. Never extend Thread in production code

5. Always use ExecutorService for thread management

6. Lambdas + Runnable = clean, modern Java
