4.4 ScheduledExecutorService

Timers, Delays, and Periodic Tasks — Done Right

The modern replacement for java.util.Timer

Chapter 4 – Executors & Thread Pools

Goodbye Timer, Hello ScheduledExecutorService

java.util.Timer (1998) had fatal flaws:

  • Single thread → one slow task blocks everything
  • Exception kills the timer
  • No thread pool, no control
Java 5 fixed it forever:
ScheduledExecutorService = thread pool + scheduling

The 4 Scheduling Methods

schedule()
schedule(Callable, delay, unit)
Run once after delay 
scheduler.schedule(() -> cleanup(), 10, MINUTES);
scheduleAtFixedRate()
scheduleAtFixedRate(Runnable, initial, period, unit)
Fixed period between start times
(overlapping possible) 
scheduler.scheduleAtFixedRate(() -> heartbeat(), 0, 5, SECONDS);
scheduleWithFixedDelay()
scheduleWithFixedDelay(Runnable, initial, delay, unit)
Fixed delay between end and next start
(never overlaps) 
scheduler.scheduleWithFixedDelay(() -> backup(), 1, 1, HOURS);
scheduleAtFixedRate vs FixedDelay
sequenceDiagram Note over FixedRate: Task takes 3s, period 5s loop FixedRate Task->>Task: Run Note over Task: 3s work end Note over FixedDelay: Task takes 3s, delay 5s loop FixedDelay Task->>Task: Run Note over Task: 3s work Task->>Task: Wait 5s end

Real-World: Heartbeat + Cleanup + Retry

Microservice Health & Maintenance
ScheduledExecutorService scheduler =
    Executors.newScheduledThreadPool(4);

// 1. Heartbeat every 30s
scheduler.scheduleAtFixedRate(
    this::sendHeartbeat, 0, 30, SECONDS);

// 2. Cleanup temp files every hour
scheduler.scheduleWithFixedDelay(
    this::cleanupTempFiles, 1, 1, HOURS);

// 3. Exponential backoff retry
AtomicInteger attempts = new AtomicInteger();
scheduler.schedule(() -> {
    if (!tryConnect() && attempts.getAndIncrement() < 5) {
        long delay = (long) Math.pow(2, attempts.get()) * 1000;
        scheduler.schedule(this, delay, MILLISECONDS);
    }
}, 1000, MILLISECONDS);

Common Pitfalls & Fixes

Long-running tasks in fixedRate
Task takes 10s, period 5s → overlapping → memory leak!
Fix: Use scheduleWithFixedDelay
Exception kills the scheduler
Uncaught exception → no more executions!
Fix: Wrap in try-catch or use submit() + Future
Never shutdown
Daemon threads → JVM won't exit cleanly
Fix: scheduler.shutdownNow() in finally

Production Patterns

// Graceful startup/shutdown
public class SchedulerManager implements AutoCloseable {
    private final ScheduledExecutorService scheduler =
        Executors.newScheduledThreadPool(4);

    public void start() {
        scheduler.scheduleAtFixedRate(this::task, 0, 1, MINUTES);
    }

    @Override
    public void close() {
        scheduler.shutdown();
        try {
            if (!scheduler.awaitTermination(60, SECONDS)) {
                scheduler.shutdownNow();
            }
        } catch (InterruptedException e) {
            scheduler.shutdownNow();
        }
    }
}
Always:
• Use newScheduledThreadPool(), not Executors factory
• Handle exceptions
• Implement graceful shutdown
• Prefer scheduleWithFixedDelay for maintenance tasks

Key Takeaways

1. ScheduledExecutorService = thread pool + scheduling

2. schedule() = one-shot delay

3. scheduleAtFixedRate() = fixed period (can overlap)

4. scheduleWithFixedDelay() = fixed delay between tasks (no overlap)

5. Never use java.util.Timer

6. Always handle exceptions and shutdown cleanly
