The High-Performance, Bounded Workhorse

Chapter 5 – Blocking Queues & Producer-Consumer

ArrayBlockingQueue — The Gold Standard

ArrayBlockingQueue is the most commonly used BlockingQueue in production.

Why?
• Fixed, bounded size → natural backpressure
• Single array + two indices → best performance
• Optional fairness → prevent starvation

Internal Structure: Circular Array

Constructor: Fairness Matters

// Unfair (default) — higher throughput
BlockingQueue queue = new ArrayBlockingQueue<>(1000);

// Fair — FIFO waiting order (slightly slower)
BlockingQueue fairQueue = new ArrayBlockingQueue<>(1000, true);
Fair = true: Threads waiting on put()/take() are served in arrival order
Fair = false: Faster, but possible starvation under heavy load

Production Pattern: Bounded Task Queue

BlockingQueue tasks = new ArrayBlockingQueue<>(5000, true);

ExecutorService executor = Executors.newFixedThreadPool(16);

for (int i = 0; i < 16; i++) {
    executor.submit(() -> {
        while (true) {
            Runnable task = tasks.take();  // Blocks when empty
            task.run();
        }
    });
}

// Submit work — blocks when queue full!
public void submit(Runnable task) throws InterruptedException {
    tasks.put(task);  // Natural backpressure
}
Benefits:
• Bounded memory
• Backpressure (slow consumers → producers wait)
• Fairness prevents starvation
• Maximum throughput

Key Takeaways

1. ArrayBlockingQueue = fixed size, circular array

2. Fastest BlockingQueue implementation

3. Bounded → natural backpressure

4. Optional fair=true → FIFO waiting

5. Use for high-throughput producer-consumer

6. The #1 choice in production systems
