Monitors: Java’s Built-in Safety

A monitor is a lock + condition variables. Every Java object is a monitor! 

// Java: synchronized = monitor enter/exit
synchronized(obj) {
    while (!condition) {
        obj.wait();  // Release lock, sleep
    }
    // critical section
    obj.notify();   // Wake one waiter
}
Under the hood: JVM uses OS mutex + condition variable
wait() → parks thread, notify() → unparks
sequenceDiagram participant T1 as Thread 1 participant M as Monitor participant T2 as Thread 2 T1->>M: enter() T1->>M: wait() → sleep T2->>M: enter() T2->>M: notify() T1->>M: wake up → re-acquire

Spinlocks: Busy-Waiting for Speed

A spinlock uses test-and-set in a loop. No sleeping! 

// C: Simple spinlock
volatile int lock = 0;

void acquire() {
    while (__sync_lock_test_and_set(&lock, 1)) {
        // spin!
    }
}

void release() {
    __sync_lock_release(&lock);
}
Best for: Lock held < 100 cycles
Worst for: Long waits → wastes CPU

Futex: The Linux Magic (Fast Userspace Lock)

Futex = spin in user space, sleep in kernel only when needed.

1. Check

Read lock word

2. TAS

Try atomic set

3. Success

Enter critical section

4. Contended

futex(WAIT) → kernel sleep

5. Wake

futex(WAKE)

// Linux syscall
futex(uaddr, FUTEX_WAIT, val, timeout);
futex(uaddr, FUTEX_WAKE, 1);
Used by: Java LockSupport.park/unpark, Go, Rust
Why? 99% fast path in user space

Monitors vs Spinlocks vs Futexes

Feature Monitor Spinlock Futex
Level Language (Java) Kernel / Library OS (Linux)
Wait Strategy Block (sleep) Spin (busy-wait) Spin → Sleep
Best For Long waits, safety Short critical sections High contention
Java Usage synchronized, wait/notify JVM internals LockSupport, ReentrantLock
Overhead High Low (if short) Very low

Java Uses All Three!

// 1. Monitor
synchronized(list) { list.add(x); }

// 2. Futex (via LockSupport)
LockSupport.park();   // → futex(WAIT)
LockSupport.unpark(t); // → futex(WAKE)

// 3. Spinlock (in JVM HotSpot)
biased locking → lightweight sync → OS mutex
ReentrantLock: Uses futex + spin on contention

Key Takeaways

1. Monitor: Java object lock + wait/notify.

2. Spinlock: Busy-wait with TAS → fast if short.

3. Futex: Spin in user, sleep in kernel → best of both.

4. Java: synchronized → monitor, ReentrantLock → futex.

5. LockSupport = direct futex access.
