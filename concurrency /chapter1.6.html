Why Terminology Matters

Confusing race condition with data race? You’ll write broken code.
This chapter is your multithreading dictionary — 30+ terms, crystal clear.

Pro Tip: Bookmark this page. Refer to it every time you debug a concurrency issue.

Essential Terms (A-Z)

Atomicity /əˈtɒmɪsɪti/
An operation that is indivisible — either fully completes or not at all.
counter++ is not atomic → 3 steps: read, increment, write
Safety JMM
Blocking
A thread pauses execution waiting for a resource (I/O, lock, condition).
thread.join(), socket.read(), lock.lock()
State I/O
Concurrency /kənˈkʌrənsi/
Multiple tasks make progress in overlapping time periods.
Web server handles 100 requests at once
Concept
Critical Section
Code that accesses shared resources and must not be executed by >1 thread at a time.
synchronized(account) { balance += amount; }
Synchronization
Daemon Thread
Background thread that does not prevent JVM from exiting.
GC, Timer, Logging threads
Lifecycle
Deadlock
Two or more threads permanently blocked, each holding a lock the other needs.
T1 holds LockA, waits for LockB
T2 holds LockB, waits for LockA
Bug Locking
Livelock
Threads are active but stuck in a loop of yielding to each other — no progress.
Two polite people stepping aside in a hallway
Bug
Monitor
Object used for synchronization. Every Java object has an intrinsic lock (monitor).
synchronized(obj) { ... }
JVM
Parallelism
Multiple tasks execute simultaneously on different CPU cores.
ForkJoinPool on 8-core CPU
Performance
Race Condition
Behavior depends on timing of uncontrolled events (thread scheduling).
if (balance > 0) withdraw(amount) → two threads see balance > 0
Bug
Starvation
A thread never gets CPU time because others keep running.
Low-priority thread in busy system
Fairness
Thread-Safe
Class or method works correctly when accessed by multiple threads.
StringBuilder (not safe), StringBuffer (safe)
Design
Visibility
Changes by one thread are seen by others (JMM guarantee).
volatile int x; → writes flush to main memory
JMM

Key Takeaways

1. Concurrency ≠ Parallelism — one is about structure, one is about execution

2. Race Condition is the root of most bugs

3. Visibility and Atomicity are JMM guarantees

4. Deadlock, Livelock, Starvation — know the difference

5. Thread-Safe = correct under concurrency

6. Use this glossary — speak the language, write better code
