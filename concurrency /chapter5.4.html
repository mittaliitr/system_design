5.4 LinkedBlockingQueue

(Optionally) Bounded — But Beware the Unbounded Default

The most misused BlockingQueue in production

Chapter 5 – Blocking Queues & Producer-Consumer

LinkedBlockingQueue — The Double-Edged Sword

LinkedBlockingQueue is a linked-list based queue.
It can be bounded or unbounded (default: Integer.MAX_VALUE!).

Danger: new LinkedBlockingQueue<>() → unbounded queue → OutOfMemoryError under backpressure!

Internal Structure: Linked Nodes

Item A
Item B
Item C
...
Item Z
Two locks:
• putLock for producers
• takeLock for consumers
→ Higher concurrency than single lock

The Infamous Constructor Trap

// WRONG — unbounded! (2.1 billion capacity)
BlockingQueue queue = new LinkedBlockingQueue<>();

// CORRECT — bounded
BlockingQueue queue = new LinkedBlockingQueue<>(1000);
Default capacity = Integer.MAX_VALUE
Producer fills queue → OOM before consumer wakes up!

Performance vs ArrayBlockingQueue

Metric ArrayBlockingQueue LinkedBlockingQueue
Throughput ~45M ops/s ~18M ops/s
Memory Fixed array Node per element
GC Pressure Low High (object allocation)
Concurrency Single lock Dual lock (put/take)
ArrayBlockingQueue wins in 95% of cases.
Use Linked only if you truly need dynamic sizing.

When LinkedBlockingQueue Makes Sense

// Rare valid use: truly unbounded (e.g., event bus)
BlockingQueue events = new LinkedBlockingQueue<>();

// Or very large bounded queue
BlockingQueue tasks = new LinkedBlockingQueue<>(1_000_000);
Valid cases:
• Event bus (unbounded)
• Very large bounded queue (>100K)
• Need separate put/take locks

Real Crash Story: The Unbounded Queue

Production Incident:
Service used new LinkedBlockingQueue<>()
Consumer slowed down → queue grew to 2 billion items → OOM
Fix: Switch to ArrayBlockingQueue(10_000) + backpressure

Key Takeaways

1. LinkedBlockingQueue = linked nodes, optional capacity

2. Default constructor = unbounded (dangerous!)

3. Slower than ArrayBlockingQueue due to allocation

4. Dual locks → higher concurrency under extreme load

5. Never use unbounded in production

6. Prefer ArrayBlockingQueue in 99% of cases
