2.5 Thread Priorities

1 to 10 — But Should You Use It?

Warning: Priority is a hint, not a guarantee

Chapter 2 – Thread Creation & Management

Thread Priority: 1 to 10

Java threads have a priority from 1 (lowest) to 10 (highest).
Default: 5 (Thread.NORM_PRIORITY).

Reality Check:
OS scheduler may ignore Java priority entirely.
Use for soft tuning — never for correctness.

The 1–10 Priority Scale

1
MIN_PRIORITY
Background tasks
5
NORM_PRIORITY
Default for all threads
10
MAX_PRIORITY
Critical real-time
// Set priority (1–10)
thread.setPriority(Thread.MIN_PRIORITY);   // 1
thread.setPriority(Thread.NORM_PRIORITY);  // 5
thread.setPriority(Thread.MAX_PRIORITY);   // 10

// Get current
int p = thread.getPriority();

Truth: On Linux, Java 10 → nice -5, Java 1 → nice +6.
But nice is just a suggestion to the scheduler.

Demo: Priority in Action (or Not)

High vs Low Priority CPU Burn
public class PriorityDemo {
    public static void main(String[] args) throws Exception {
        Thread low = new Thread(PriorityDemo::burnCPU, "LOW");
        Thread high = new Thread(PriorityDemo::burnCPU, "HIGH");

        low.setPriority(Thread.MIN_PRIORITY);  // 1
        high.setPriority(Thread.MAX_PRIORITY); // 10

        low.start();
        high.start();

        Thread.sleep(5000);
        low.interrupt();
        high.interrupt();
    }

    static void burnCPU() {
        long count = 0;
        while (!Thread.currentThread().isInterrupted()) {
            count++;
        }
        System.out.println(Thread.currentThread().getName() + ": " + count);
    }
}
Typical Output (Linux):
HIGH: 1,842,391,201
LOW: 1,201,847,102
HIGH gets ~50% more CPU — but not guaranteed.

Priority Constants & API

Constant Value Use Case
Thread.MIN_PRIORITY 1 Background cleanup, logging
Thread.NORM_PRIORITY 5 Default — use for most threads
Thread.MAX_PRIORITY 10 Real-time UI, critical sensors

Myths vs Reality

Myth: Thread with priority 10 runs 10× faster
Reality: No. It just gets more chances to run.
Myth: Priority solves starvation
Reality: No. Use ReentrantLock(true) for fairness.
Myth: All OS respect Java priority
Reality: macOS often ignores it completely.

When to Use Priority

Safe Use Cases
  • UI threads: MAX_PRIORITY for responsiveness
  • Background analytics: MIN_PRIORITY
  • Real-time data processing: 8–10
Never: Use priority to enforce correctness or ordering.
That’s what synchronized, Locks, and Latches are for.

Key Takeaways

1. Priority: 1 (min) to 10 (max), default 5

2. OS may ignore Java priority

3. Use for soft performance tuning only

4. Never rely on priority for correctness

5. MIN_PRIORITY for background, MAX for UI

6. Priority inversion is real — avoid mixing high/low
