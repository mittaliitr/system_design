1.4 Java’s Thread Model

From Java Thread to OS Thread to CPU Core

How the JVM maps Thread objects to real concurrency

Chapter 1 – Introduction to Multithreading in Java

Java Threads = OS Threads

Java does not have its own thread scheduler. Every java.lang.Thread is a native OS thread (1:1 mapping).

Key Fact: new Thread() to start() to OS pthread (Linux) or Win32 thread

Two Ways to Create a Thread

Extend Thread Legacy 
class Worker extends Thread {
    public void run() {
        System.out.println("Working...");
    }
}

Thread t = new Worker();
t.start();
Implement Runnable Recommended 
Runnable task = () -> {
    System.out.println("Task running");
};

Thread t = new Thread(task);
t.start();
Why Runnable?
to Supports composition
to Works with ExecutorService
to Enables Callable and return values

User Threads vs. Daemon Threads

User Threads
Main thread
Worker threads
Thread pool tasks
Daemon Threads
GC threads
Finalizer
Timer threads
// Daemon thread example
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("Background task...");
        Thread.sleep(1000);
    }
});
daemon.setDaemon(true);  // Must set BEFORE start()
daemon.start();
Rule: JVM exits when all user threads finish, even if daemon threads are running.

Thread Groups: Logical Grouping

ThreadGroup group = new ThreadGroup("Workers");

Thread t1 = new Thread(group, () -> { /* task */ }, "Worker-1");
Thread t2 = new Thread(group, () -> { /* task */ }, "Worker-2");

group.list();           // Print all threads
group.interrupt();      // Interrupt all
Use Case: to Graceful shutdown
to Monitoring
to Security boundaries

Key Takeaways

1. Java threads to 1:1 OS threads (no green threads)

2. Prefer Runnable or Callable over extending Thread

3. start() to OS thread; run() to just method call

4. Daemon threads die when JVM exits

5. Use ThreadGroup for management

6. 6 states: NEW to RUNNABLE to BLOCKED to TERMINATED
