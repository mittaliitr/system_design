6.2 Thread.ofVirtual().start()

Creating Millions of Threads — The New Way

From new Thread() to Thread.ofVirtual()

Chapter 6 – Project Loom

The Two New Ways to Create Virtual Threads

Thread.ofVirtual() Recommended 
// Builder style — most flexible
Thread virtual = Thread.ofVirtual()
    .name("worker-", 0)
    .uncaughtExceptionHandler((t, e) -> log(e))
    .start(() -> work());

virtual.join(); // Optional
Executors.newVirtualThreadPerTaskExecutor() For Executors 
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1_000_000; i++) {
        executor.submit(() -> task(i));
    }
} // Auto-shutdown + join
Key:
• Thread.ofVirtual() = single thread
• newVirtualThreadPerTaskExecutor() = one virtual thread per task (perfect for servers)

Old World vs New World

Old (Platform Threads) Avoid 
new Thread(() -> task()).start();  // Expensive!
Max ~10,000 threads
High memory
Slow creation
New (Virtual Threads) Use This 
Thread.ofVirtual().start(() -> task());
// or
executor.submit(() -> task());
Millions of threads
~KB per thread
Near-zero cost

One Million Virtual Threads — It Just Works

Run This in Java 21+
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 1_000_000).forEach(i -> {
        executor.submit(() -> {
            Thread.sleep(1000);
            System.out.println("Task " + i + " on " + Thread.currentThread());
        });
    });
} // Auto-joins all 1M threads!
System.out.println("All done!");
Result:
• ~200–500 MB RAM
• Runs in ~1 second (plus sleep)
• Same code with platform threads → OOM in < 10k

Thread.Builder — Full Control

Thread.Builder builder = Thread.ofVirtual()
    .name("worker-", 1)
    .uncaughtExceptionHandler((t, e) -> log(e));

Thread t1 = builder.start(task1);
Thread t2 = builder.start(task2);
Also works for platform threads:
Thread.ofPlatform().daemon(true).start()

100% Backward Compatible

All existing code works unchanged
• synchronized, ThreadLocal, join(), interrupt()
• ThreadLocal → still per-thread (virtual thread)
• No breaking changes 
// Your 10-year-old code works perfectly on virtual threads
synchronized(lock) {
    Thread.sleep(1000);  // Now unmounts carrier thread!
}

Key Takeaways

1. Thread.ofVirtual().start() = single virtual thread

2. newVirtualThreadPerTaskExecutor() = one VT per task

3. Millions of threads → KB memory, near-zero cost

4. Try-with-resources → auto-join all tasks

5. Fully backward compatible

6. Never use new Thread() again
