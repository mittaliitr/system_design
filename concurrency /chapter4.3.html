4.3 submit() vs execute()

Future, Callable, CompletableFuture

From fire-and-forget to async/await-style programming

Chapter 4 – Executors & Thread Pools

Two Ways to Submit Tasks

ExecutorService gives you two methods:

  • execute(Runnable) → fire-and-forget
  • submit(...) → returns Future (get result, cancel, etc.)
Rule: Always prefer submit() — it’s strictly superior.

execute() vs submit()

execute(Runnable) Legacy 
executor.execute(() -> {
    // No way to get result
    // Exception dies silently!
});
Problems:
• No return value
• Exception swallowed
• Cannot cancel
submit(Runnable/Callable) Recommended 
Future f = executor.submit(() -> {
    // Can throw checked exceptions
});

Future f2 = executor.submit(() -> "Result");
String result = f2.get();  // Blocks
Benefits:
• Get result
• Exception in ExecutionException
• Cancel task

Callable — Runnable That Returns

// Old way — no return
Runnable task = () -> compute();

// New way — returns value + throws checked
Callable task = () -> computeExpensive();

Future future = executor.submit(task);
String result = future.get();  // Blocks until done
Callable is the modern replacement for Runnable when you need results.

Future: The Promise of a Result

graph TD A[submit(task)] --> B[Future Object] B -->|get()| C[Result or Exception] B -->|get(timeout)| D[TimeoutException] B -->|cancel(true)| E[InterruptedException] B -->|isDone()| F[true/false] style B fill:#9b59b6,stroke:#9b59b6,color:white 
Future future = executor.submit(() -> "Hello");

try {
    String result = future.get(10, TimeUnit.SECONDS);
} catch (TimeoutException e) {
    future.cancel(true);  // Interrupt if running
}

CompletableFuture — Async/Await for Java

Chaining
CompletableFuture.supplyAsync(() -> fetchUser())
    .thenApply(user -> enrich(user))
    .thenAccept(System.out::println);
Combining
var user = fetchUserAsync();
var orders = fetchOrdersAsync(user.id);

CompletableFuture.allOf(user, orders)
    .thenRun(() -> render(user, orders));
Exception Handling
fetchAsync()
    .exceptionally(ex -> fallback())
    .thenAccept(result -> use(result));
CompletableFuture = Future on steroids
Non-blocking, composable, reactive-style

Golden Rules

Never:
• Use execute() (swallows exceptions)
• Block on future.get() in high-throughput code
• Forget finally { executor.shutdown() }
Always:
• Prefer submit(Callable) or CompletableFuture
• Use thenApply/thenAccept for non-blocking
• Handle ExecutionException and CancellationException

Key Takeaways

1. execute() = fire-and-forget (dangerous)

2. submit() = returns Future (get result, cancel)

3. Callable = Runnable that returns value + throws

4. CompletableFuture = async/await style

5. Always handle exceptions and timeouts

6. Never block the main thread — chain with then...
