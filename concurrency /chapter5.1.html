What Happens Without Producer-Consumer?

Problem 1: Busy Waiting
// CPU burns 100% waiting
while (buffer.isEmpty()) { }  // Spins forever!
Wastes CPU, drains battery
Problem 2: Race Conditions
// No synchronization
buffer.add(item);  // Two producers → corruption
Lost or corrupted items
Problem 3: No Backpressure
// Producer runs wild
while (true) buffer.add(produce());  // OOM!
Memory explosion

The Perfect Solution: BlockingQueue

BlockingQueue queue = new ArrayBlockingQueue<>(100);

executor.submit(() -> {
    while (true) {
        String item = produce();
        queue.put(item);  // Blocks when full — backpressure!
    }
});

executor.submit(() -> {
    while (true) {
        String item = queue.take();  // Blocks when empty
        consume(item);
    }
});
Magic:
• put() blocks when full
• take() blocks when empty
• Thread-safe, no explicit
• No busy waiting, no race conditions

Classic wait()/notify() Version (Educational)

class BoundedBuffer {
    private final List buffer = new ArrayList<>();
    private final int capacity;
    private final Object lock = new Object();

    public BoundedBuffer(int capacity) {
        this.capacity = capacity;
    }

    public void put(T item) throws InterruptedException {
        synchronized(lock) {
            while (buffer.size() == capacity) {
                lock.wait();  // Release lock, sleep
            }
            buffer.add(item);
            lock.notifyAll();
        }
    }

    public T take() throws InterruptedException {
        synchronized(lock) {
            while (buffer.isEmpty()) {
                lock.wait();
            }
            T item = buffer.remove(0);
            lock.notifyAll();
            return item;
        }
    }
}
Works — but error-prone
Modern Java: Use BlockingQueue instead

Why This Pattern Wins

Benefits:
• Decoupling: Producers and consumers independent
• Backpressure: Slow consumer → producer waits
• Load smoothing: Bursts absorbed by queue
• Scalability: Add more producers/consumers independently

Key Takeaways

1. Producer-Consumer = decoupled, scalable, backpressured

2. Core problem: coordinating producers and consumers

3. BlockingQueue = the perfect solution

4. put() blocks when full, take() blocks when empty

5. Powers Kafka, message queues, thread pools

6. Never implement your own — use java.util.concurrent
