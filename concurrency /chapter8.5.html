The Cloud Kitchen Nightmare

One kitchen, 20+ brands (Swiggy/Zomato), 1000+ incoming orders.
Each order has a preparation time and must be ready exactly on time.

Constraints:
• Only N burners/stations
• Orders must start at the right time (not too early → cold food, not too late → angry customer)
• Real-time re-scheduling when orders are delayed

Key:
• PriorityBlockingQueue ordered by planned start time
• Worker threads take() next order when burner free
• Delay → re-insert affected orders with new start time

Core Scheduler Code (GeekTrust Style)

record Order(String id, int prepMinutes, LocalDateTime deliveryTime)
    implements Delayed {

    public long getDelay(TimeUnit unit) {
        LocalDateTime startTime = deliveryTime.minusMinutes(prepMinutes);
        return unit.convert(Duration.between(LocalDateTime.now(), startTime).toMillis(),
                            TimeUnit.MILLISECONDS);
    }

    public int compareTo(Delayed o) {
        return Long.compare(this.getDelay(TimeUnit.NANOSECONDS),
                           o.getDelay(TimeUnit.NANOSECONDS));
    }
}

DelayQueue queue = new DelayQueue<>();
ExecutorService burners = Executors.newFixedThreadPool(10); // 10 burners

// Consumer workers
for (int i = 0; i < 10; i++) {
    burners.submit(() -> {
        while (true) {
            try {
                Order order = queue.take();  // Blocks until ready
                cook(order);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    });
}

// Producer — new order arrives
public void acceptOrder(Order order) {
    queue.put(order);  // Will be taken at correct time
}

Real-World Challenges Solved

Dynamic Re-scheduling
Order delayed 5 min → push back all dependent orders
Solution: Remove from queue + re-insert with new time
Priority Orders
VIP / Prime orders jump the queue
Solution: Custom Comparator in PriorityBlockingQueue
Burner Allocation
Different food types need different stations
Solution: Multiple queues per station type
Backpressure
Too many orders → reject new ones
Solution: Bounded queue + rejection policy

Key Takeaways from Cloud Kitchens

1. Real-time scheduling = DelayQueue or PriorityBlockingQueue

2. Workers = fixed thread pool (number of burners)

3. Dynamic re-scheduling = remove + re-insert

4. Backpressure = bounded queues

5. This pattern used by Swiggy, Zomato, Rebel Foods

6. Perfect interview question: "Design a cloud kitchen scheduler"
