4.2 ExecutorService & Thread Pools

The Heart of Scalable Java Concurrency

Fixed, Cached, Single, Scheduled — choose your weapon

Chapter 4 – Executors & Thread Pools

ExecutorService: The New Way

ExecutorService is an abstraction over thread management.
You give it tasks — it decides how and when to run them.

Core Interface:
void execute(Runnable) — fire and forget
Future<?> submit(Runnable/Callable) — get result
void shutdown() — clean exit

The 4 Built-in Thread Pools

newFixedThreadPool(n) Most Common
Fixed number of threads. Ideal for CPU-bound or controlled concurrency.
Web servers, batch processing, bounded parallelism 
ExecutorService pool = Executors.newFixedThreadPool(8);
newCachedThreadPool()
Unlimited threads (reused). Creates new if idle >60s.
Short-lived async tasks (e.g., GUI apps) 
ExecutorService pool = Executors.newCachedThreadPool();
newSingleThreadExecutor()
Exactly one thread. Tasks run sequentially.
Order-critical tasks, Swing workers 
ExecutorService pool = Executors.newSingleThreadExecutor();
newScheduledThreadPool(n)
For delayed or periodic tasks (Timer replacement).
Heartbeats, cleanup, retries 
ScheduledExecutorService scheduler =
    Executors.newScheduledThreadPool(4);

ExecutorService Lifecycle

// Graceful shutdown
executor.shutdown();                    // No new tasks
executor.awaitTermination(60, SECONDS); // Wait up to 60s

// Forceful
List pending = executor.shutdownNow();  // Returns unfinished

submit() vs execute()

Method Returns Exception Handling Use When
execute(Runnable) void Exception in thread → uncaught Fire-and-forget
submit(Runnable) Future<?> Exception wrapped in ExecutionException Need result or error handling
submit(Callable) Future<T> Returns value Need return value

ForkJoinPool — The Default for Parallel Streams

commonPool() = ForkJoinPool with Runtime.getRuntime().availableProcessors() - 1 threads
Used by stream().parallel() 
// Custom ForkJoinPool
ForkJoinPool pool = new ForkJoinPool(8);
pool.submit(() -> stream.parallel().forEach(...));

Golden Rules

Never use Executors.newXXX() in libraries — they create unbounded queues
Always create your own ThreadPoolExecutor 
// Production-ready
ExecutorService executor = new ThreadPoolExecutor(
    8, 8,                                 // core = max
    60L, TimeUnit.SECONDS,                // idle timeout
    new LinkedBlockingQueue<>(1000),      // bounded queue
    new ThreadFactoryBuilder().setNameFormat("worker-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy()  // backpressure
);

Key Takeaways

1. ExecutorService = thread pool + lifecycle

2. newFixedThreadPool = most common

3. submit() > execute() (better error handling)

4. Always shutdown() + awaitTermination()

5. ForkJoinPool.commonPool() powers parallel streams

6. In libraries: new ThreadPoolExecutor(...), not Executors
