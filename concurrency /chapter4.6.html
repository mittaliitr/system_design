4.6 Parallel Streams

Massive Parallelism in One Line of Code

The easiest way to use all CPU cores — powered by Fork/Join

Chapter 4 – Executors & Thread Pools

From Sequential to Parallel — Just Add .parallel()

Java 8 introduced Streams — functional-style operations on collections.
Add .parallel() → automatic parallel execution using ForkJoinPool.commonPool().

One word turns 1 core into all cores.

Before Java 8 vs After

Sequential Stream 1 core 
long sum = longStream
    .filter(n -> n % 2 == 0)
    .map(n -> n * n)
    .sum();  // 1 thread, 1 core
Parallel Stream All cores 
long sum = longStream
    .parallel()          // Magic!
    .filter(n -> n % 2 == 0)
    .map(n -> n * n)
    .sum();  // Fork/Join does the rest

Pitfalls & Best Practices

Never do:
• Blocking I/O inside parallel stream
• Shared mutable state
• Side effects in lambdas 
// WRONG — shared mutable state!
AtomicLong counter = new AtomicLong();
list.parallelStream().forEach(i -> counter.incrementAndGet());

// CORRECT — stateless
long sum = list.parallelStream()
    .mapToLong(Long::longValue)
    .sum();
Best Practices:
• Use for CPU-bound, stateless operations
• Prefer primitive streams (IntStream)
• Avoid findFirst() on parallel (non-deterministic)
• Use findAny() or collect() with combiner

Custom ForkJoinPool (Advanced)

ForkJoinPool pool = new ForkJoinPool(16);

pool.submit(() ->
    list.parallelStream()
        .map(this::process)
        .collect(toList())
).join();
Use when:
• You need more threads than commonPool
• Isolate from other parallel streams

Key Takeaways

1. .parallel() = massive parallelism in one word

2. Powered by ForkJoinPool.commonPool()

3. Up to N-1× speedup on N cores

4. Must be stateless and side-effect free

5. Never block or mutate shared state

6. Use primitive streams for best performance
