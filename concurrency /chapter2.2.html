Chapter 2 – Thread Creation & Management

Every Thread Has a Life

A Java thread goes through 6 well-defined states from creation to termination. Knowing these states is essential for:

  • Debugging stuck threads
  • Monitoring thread pools
  • Writing correct shutdown logic
  • Passing Java certification exams
Key API: Thread.currentThread().getState() → returns Thread.State enum

RUNNABLE

BLOCKED
Waiting to acquire a monitor lock (synchronized block/method).

WAITING
Indefinitely waiting for another thread (Object.wait(), Thread.join()).
wait(), join()

Waiting with timeout (sleep(), wait(ms), join(ms)).

State Transition Triggers

From → To Trigger Method / Event Example
NEW → RUNNABLE start() thread.start()
RUNNABLE → BLOCKED Entering synchronized (contended lock) synchronized(obj) {}
RUNNABLE → WAITING Object.wait(), Thread.join(), LockSupport.park() obj.wait()
RUNNABLE → TIMED_WAITING Thread.sleep(ms), wait(ms), join(ms) Thread.sleep(1000)
BLOCKED → RUNNABLE Lock acquired Monitor entered
WAITING → RUNNABLE notify() or notifyAll() obj.notify()
TIMED_WAITING → RUNNABLE Timeout expires or notify After 1 second
RUNNABLE → TERMINATED run() returns or throws End of run()

Live Demo: Watch States Change

Thread State Observer
public class StateDemo {
    public static void main(String[] args) throws Exception {
        Thread thread = new Thread(() -> {
            System.out.println("Thread running...");
            try { Thread.sleep(2000); }
            catch (InterruptedException e) { }
            System.out.println("Thread done.");
        });

        printState(thread, "Created");
        thread.start();
        printState(thread, "Started");

        Thread.sleep(500);
        printState(thread, "Sleeping");

        thread.join();
        printState(thread, "Joined");
    }

    static void printState(Thread t, String event) {
        System.out.printf("%s: %s%n", event, t.getState());
    }
}
Expected Output:
Created: NEW
Started: RUNNABLE
Sleeping: TIMED_WAITING
Joined: TERMINATED

Myths vs. Reality

Myth: RUNNABLE = Running
Reality: RUNNABLE means eligible to run. Could be waiting for CPU.
Myth: BLOCKED = Deadlock
Reality: BLOCKED is normal. Deadlock is a pattern of blocked threads.
Myth: TERMINATED threads can restart
Reality: Once TERMINATED, start() throws IllegalThreadStateException.

Key Takeaways

1. 6 states: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED

2. RUNNABLE ≠ actually running — it's ready

3. BLOCKED = waiting for lock, WAITING = waiting for signal

4. Use Thread.getState() in logs and monitoring

5. TERMINATED threads cannot be restarted

6. Master states → master debugging
