Koko Eating Bananas — Explanation + Java Solution

LeetCode 875 — Binary search on the answer (first-true pattern)

This page explains the problem, why binary search is the right tool, the true/false boundary pattern used, a dry run example, and a well-commented Java implementation you can copy.

Problem (short)

Given piles of bananas and h hours, Koko eats k bananas per hour (she picks one pile per hour and eats up to k from it; if pile < k she finishes it and wastes the hour). Find the minimum integer k so she can finish all piles within h hours.

Key idea — monotonic predicate

Define canFinish(k) = whether Koko can finish all piles in ≤ h hours at speed k. This predicate is monotonic: if canFinish(k) is true, then canFinish(k') is also true for any k' > k. That gives a boolean sequence like:

false, false, ..., false, true, true, ..., true

We want the first true index (minimum k making the predicate true) — ideal for binary search.

Bounds for binary search

  • left = 1 (minimum possible speed)
  • right = max(piles) (no need to try speeds larger than the biggest pile)

Checking function

To compute hours needed at speed k, sum ceil(pile / k) across piles. Use integer math: (pile + k - 1) / k. If total hours > h, return false early.

Dry run (brief)

piles = [3, 6, 7, 11], h = 8
  • maxPile = 11 → search [1, 11]
  • mid=6 → hours = 1+1+2+2 = 6 → true → shrink right
  • mid=3 → hours = 1+2+3+4 = 10 → false → increase left
  • mid=4 → hours = 1+2+2+3 = 8 → true → answer = 4

Java implementation (first-true binary search)

// Koko Eating Bananas — Java solution (binary search on answer)
public class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        // right bound = max pile
        int maxPile = 0;
        for (int x : piles) maxPile = Math.max(maxPile, x);

        int left = 1;
        int right = maxPile;
        int answer = maxPile;

        // first-true pattern: find smallest k such that canFinish(k) is true
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (canFinish(piles, mid, h)) {
                answer = mid;      // mid works, try smaller
                right = mid - 1;
            } else {
                left = mid + 1;    // mid too slow, try larger
            }
        }
        return answer;
    }

    private boolean canFinish(int[] piles, int k, int h) {
        long hoursNeeded = 0L; // use long to avoid overflow
        for (int pile : piles) {
            // ceil(pile / k) using integer math
            hoursNeeded += (pile + (long)k - 1) / k;
            if (hoursNeeded > h) return false; // early exit
        }
        return hoursNeeded <= h;
    }

    // small main for quick local testing
    public static void main(String[] args) {
        Solution s = new Solution();
        int[] piles = {3, 6, 7, 11};
        int h = 8;
        System.out.println(s.minEatingSpeed(piles, h)); // prints 4
    }
}

Variant: while (left < right) style

// alternative binary search style returning left
int left = 1, right = maxPile;
while (left < right) {
    int mid = left + (right - left) / 2;
    if (canFinish(piles, mid, h)) {
        right = mid; // mid might be the answer
    } else {
        left = mid + 1;
    }
}
// left == right == minimum good k

Tips & gotchas

  • Always use long when summing hours to avoid overflow on big inputs.
  • Compute mid as left + (right - left) / 2 to avoid overflow.
  • Early exit from the hour-summing loop helps performance.
