💡 LeetCode 3346 — Maximum Frequency of an Element After Performing Operations I

🧩 Problem Explanation

You are given an integer array nums, and two integers k and numOperations.

You can perform at most numOperations operations. Each operation allows you to:

  • Pick one index i (not chosen before).
  • Add any integer in the range [-k, k] to nums[i].

Your goal: maximize the frequency of a single value in the array after performing these operations.

Return the maximum possible frequency.

📘 Example

Input: nums = [1, 4, 5], k = 1, numOperations = 2
Output: 2

Explanation:
We can do the following:
- Keep nums[0] = 1
- Keep nums[1] = 4
- Change nums[2] = 5 → 4  (subtract 1)

Now the array is [1, 4, 4], and 4 appears twice.
Maximum frequency = 2.

🧠 Intuition

Every element nums[i] can be changed to any value in [nums[i] - k, nums[i] + k].

Two elements can be made equal if their ranges overlap.

So the problem becomes: find the largest group of elements whose ranges overlap (within ±k), limited by how many indices (numOperations) you can modify.

⚙️ Approach

  1. Sort the array nums.
  2. Use two pointers (left and right) to maintain a sliding window of elements that can all become equal within ±k.
  3. If nums[right] - nums[left] > 2 * k, move left forward (shrink the window).
  4. The current window size gives how many can be equal, but you can only change numOperations of them — so limit by min(windowSize, numOperations + 1).
  5. Track the maximum window size → that’s your answer.

💻 Java Code


import java.util.*;

public class Solution {
    public int maxFrequency(int[] nums, int k, int numOperations) {
        Arrays.sort(nums);
        int n = nums.length;
        int left = 0;
        int maxFreq = 1;

        for (int right = 0; right < n; right++) {
            // Shrink the window if range exceeds 2*k
            while (nums[right] - nums[left] > 2 * k) {
                left++;
            }

            int windowSize = right - left + 1;
            int possible = Math.min(windowSize, numOperations + 1);
            maxFreq = Math.max(maxFreq, possible);
        }

        return maxFreq;
    }

    public static void main(String[] args) {
        Solution sol = new Solution();
        int[] nums = {1, 4, 5};
        int k = 1, numOps = 2;
        System.out.println(sol.maxFrequency(nums, k, numOps)); // Output: 2
    }
}

⏱️ Complexity

  • Time: O(n log n) — due to sorting.
  • Space: O(1) — two pointers and variables.

🗝️ Key Takeaway

This is a range-overlap + sliding window problem.
By sorting, you can easily find contiguous segments where all elements can become equal within ±k, limited by numOperations.
