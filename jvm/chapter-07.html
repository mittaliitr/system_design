Memory Management: From PermGen to Metaspace and Beyond

How Java memory evolved across decades — GC generations, PermGen failures, the rise of Metaspace, native allocation, and tuning strategies for modern JVMs.

The JVM Memory Landscape

A JVM process consists of multiple memory regions: the heap, metaspace, code cache, thread stacks, direct/native buffers, GC metadata, JIT structures, and more. Understanding them helps avoid crashes, leaks, and OOM errors.

The Heap (Young + Old)

Most object allocations happen on the heap. Modern GC algorithms use generations:

  • Youth generation: Eden + Survivor spaces; frequent GC cycles.
  • Old generation: Long-lived objects promoted over time.

PermGen: The Historical Problem Child

Up to Java 7, the Permanent Generation stored:

  • Class metadata (method info, field layout, constant pool)
  • Interned Strings
  • Static variables
  • Annotations

Common failures:

java.lang.OutOfMemoryError: PermGen space

It was small, fixed-size, not dynamically expandable, and classloader-heavy frameworks (Tomcat, Spring, Hibernate) frequently exhausted it.

Metaspace: The Modern Replacement

From Java 8+, class metadata moved to native memory and PermGen was replaced by Metaspace.

  • Dynamically grows (up to OS limits)
  • Class metadata now lives outside the heap
  • String intern pool moved to heap (not in metaspace)
  • Better classloader garbage collection

Key tuning options

-XX:MaxMetaspaceSize=256m
-XX:MetaspaceSize=64m
-XX:MinMetaspaceFreeRatio=40
-XX:MaxMetaspaceFreeRatio=70

Native Memory & Direct Buffers

Beyond heap + metaspace, JVM apps use native memory for:

  • DirectByteBuffer memory
  • JIT compiled code
  • GC metadata structures
  • Thread stacks
  • JNI allocations

Native memory leaks often come from unmanaged buffers or non-finalized resources.

Garbage Collectors: The Evolution

  • Serial GC — simple, stop-the-world (embedded devices).
  • Parallel GC — high throughput, stop-the-world, multi-threaded.
  • CMS (Deprecated) — low pause, concurrent marking; replaced by G1.
  • G1 GC (Default) — region-based, predictable pause times.
  • ZGC — sub-millisecond pauses, huge heaps (multi-terabyte).
  • Shenandoah — concurrent compaction, ultra-low pause.

Debugging Memory Issues

  • jmap -heap — heap summary
  • jcmd GC.class_stats — class metadata visibility
  • jvisualvm / Java Mission Control — live analysis
  • Native Memory Tracking (NMT)
java -XX:NativeMemoryTracking=detail -XX:+UnlockDiagnosticVMOptions -XX:+PrintNMTStatistics -version
