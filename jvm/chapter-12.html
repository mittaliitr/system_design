Java Flight Recorder & The Best Profiler You Already Own

Built-in JVM profiling and event recording tool to monitor, diagnose, and optimize Java applications with minimal overhead.

What is Java Flight Recorder (JFR)?

Java Flight Recorder is a powerful, low-overhead profiling and event collection framework integrated into the HotSpot JVM since Java 7 (commercial feature) and open-sourced with Java 11+. It records detailed runtime information about the JVM and Java application behavior.

  • Records CPU usage, memory allocation, garbage collection, thread activity, locking, I/O events, and more.
  • Designed to have minimal impact on application performance (< 1-2% overhead).
  • Enables continuous monitoring and on-demand recordings.

Why use JFR?

  • Low overhead: JFR’s design allows it to run continuously in production without significantly affecting performance.
  • Rich insights: Provides deep visibility into JVM internals and application behavior.
  • Integrated tools: Works seamlessly with tools like Java Mission Control (JMC) for rich visualizations.
  • Event-based: Captures both system-level and application-level events (custom events can be defined).

How to use Java Flight Recorder

Starting a recording from the command line:

java -XX:StartFlightRecording=duration=60s,filename=myrecording.jfr -jar myapp.jar

This command runs the application and records JVM events for 60 seconds, saving the recording in myrecording.jfr.

You can also control JFR dynamically via JMX or Java Mission Control (JMC) to start/stop recordings without restarting the JVM.

Opening and analyzing recordings is typically done with Java Mission Control, which provides visualizations and event timelines to pinpoint performance bottlenecks.

Key events recorded by JFR

  • CPU sampling - stack traces sampled periodically to show hotspots.
  • Allocation events - objects allocated on heap with size and class info.
  • Garbage collection - pause times and GC statistics.
  • Thread activity - thread start/stop, blocking, and contention.
  • Lock profiling - monitor enter/exit events to detect contention.
  • I/O events - file and network I/O with timings.

Best practices and tips

  • Use JFR in production for continuous profiling to catch hard-to-reproduce issues.
  • Start with default event settings, then customize based on your needs.
  • Combine JFR with other JVM diagnostics like GC logs for comprehensive monitoring.
  • Analyze recordings with Java Mission Control or open-source tools like jfr-dump.
  • Define custom events in your application code to capture domain-specific metrics.
