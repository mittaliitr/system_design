Safepoints, Handshakes & The Hidden Pulse of the JVM

How the JVM safely pauses and coordinates threads to perform crucial maintenance and profiling operations.

What are Safepoints?

Safepoints are well-defined moments during JVM execution where all Java threads are paused to allow the JVM to perform global operations safely, such as garbage collection, thread stack inspection, and biased locking revocation.

  • Threads reach safepoints at safe locations in the code (e.g., loop backedges, method calls).
  • At a safepoint, JVM can safely manipulate thread states and memory.
  • Safepoint pauses are necessary to ensure JVM correctness for tasks like GC.

What is a Handshake?

A handshake is a lighter synchronization mechanism used by the JVM to coordinate individual threads without fully stopping all threads at a safepoint.

  • Enables the JVM to perform quick thread-local operations (like thread suspension or deoptimization) without full safepoint pause.
  • Works by requesting a specific thread to stop at a safe point via a handshake request.
  • Reduces latency compared to full safepoints.

Why are Safepoints & Handshakes Important?

  • Allow the JVM to perform garbage collection safely by stopping all threads.
  • Enable runtime optimizations like code deoptimization and recompilation.
  • Used in JVM diagnostics for thread dumps and profiling.
  • Ensure consistent and safe updates to JVM internal data structures.

How Do Safepoints Work?

When a safepoint is requested:

  1. The JVM signals all Java threads to pause at their next safepoint poll.
  2. Threads reach a safepoint by checking safepoint polls inserted at safe code locations.
  3. Once all threads are paused, the JVM performs the requested operation (e.g., GC).
  4. After completion, threads are resumed.

This mechanism relies on carefully placed safepoint polls that cause minimal runtime overhead.

Common Safepoint Operations

  • Garbage collection (major and minor).
  • Deoptimization and code cache cleanup.
  • Thread stack inspection for thread dumps.
  • Biased locking revocation.

Measuring Safepoint Impact

JVM options can help monitor safepoint statistics:

-XX:+PrintSafepointStatistics
-XX:PrintSafepointStatisticsCount=1
-XX:+PrintGCApplicationStoppedTime

This logs safepoint pauses and durations to help identify performance issues caused by safepoints.
